## ⚠️ Pre-Test Notes

### Build is mandatory
The `assets/` directory is **not committed to git** (webpack-generated). You **must** run the build before testing, otherwise the committed asset stubs are stale and may cause issues:
```bash
git checkout dev && git pull origin dev
npm install && npm run build
```

### Regression discovered and fixed mid-test
The prior commit `fed97db` ("fix: PCP Plugin Check compliance errors") introduced a **PHP fatal error** in `includes/core/class-asset-optimizer.php` by placing an `if (!defined('ABSPATH'))` check before `declare(strict_types=1)`. This made the entire site non-functional. The commit `b9d33df` fixed this file. All other files in the codebase have only docblock comments before `declare` — which is valid PHP.

**Important:** On a fresh WordPress install, the permalink structure defaults to "plain" (`?p=123`). With plain permalinks, `/sitemap.xml` returns the homepage instead of the sitemap. After configuring pretty permalinks (e.g. `/%postname%/`), `sitemap.xml` returns valid XML with the WordPress XSL stylesheet:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="http://site/wp-sitemap-index.xsl" ?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">...
```

**This is expected behavior** — any fresh WP install needs permalink configuration. On a real user site, this would already be configured.

### ⚠️ 6. Console Errors (Priority: MEDIUM)

| Check | Result | Notes |
|-------|--------|-------|
| No red ThinkRank errors on admin pages | ⚠️ 1 ERROR | Dashboard has 1 REST 500 error |
| No red errors on frontend | ✅ PASS | No console errors |

**Console error found on Dashboard:**
```
Failed to load resource: 500 (Internal Server Error)
URL: /wp-json/thinkrank/v1/content-brief/list
```

**Root cause:** The `content-brief/list` endpoint calls `AI_Manager::get_client()` which throws an exception when no AI provider API key is configured. The exception propagates to a 500 response instead of being caught by the "no API key" fallback handler.

**Impact:** The Content Brief widget on the Dashboard shows an error state until an AI API key is configured. All other Dashboard widgets function normally.

**Additional finding:** Duplicate `<meta name="robots">` tags on the frontend:
- WordPress core outputs: `max-image-preview:large`
- ThinkRank outputs: `index, follow, max-snippet:-1, max-video-preview:-1, max-image-preview:large`

ThinkRank should suppress WordPress core's robots meta to avoid the duplicate. This is a minor SEO hygiene issue, not a breaking bug.

## Bugs Found

### 🔴 BUG-1 (FIXED) — PHP Fatal Error — class-asset-optimizer.php
- **Commit:** `fed97db` introduced it; `b9d33df` fixed it
- **Symptom:** Every page returned a PHP fatal error making the plugin completely non-functional
- **Cause:** ABSPATH check placed before `declare(strict_types=1)`
- **Status:** Fixed in current dev HEAD (`b9d33df`)

---

### 🟡 BUG-2 (OPEN) — content-brief/list returns HTTP 500 when no AI key configured
- **URL:** `GET /wp-json/thinkrank/v1/content-brief/list`
- **Condition:** Fresh install with no AI provider API key set
- **Expected:** HTTP 200 with empty array `{ success: true, data: [], total: 0 }`
- **Actual:** HTTP 500 — the exception thrown by `AI_Manager::get_client()` bypasses the "no API key" fallback handler in `Content_Brief_Endpoint::get_briefs()`
- **Impact:** Content Brief widget on Dashboard shows an error. Low severity — resolved once API key is configured.

---

### 🟡 BUG-3 (OPEN) — Duplicate robots meta tag on frontend
- **Symptom:** Two `<meta name="robots">` tags output on every page
- **Cause:** ThinkRank doesn't remove WordPress core's robots meta before outputting its own
- **Impact:** Minor SEO hygiene issue. Both tags are compatible; no harm but not clean.

## Recommendations

1. **Fix BUG-2** — In `Content_Brief_Endpoint::get_briefs()`, catch the exception from `get_generator()` more broadly, before calling `get_user_briefs()`, or ensure `AI_Manager::get_client()` returns null instead of throwing when no key is configured.

2. **Fix BUG-3** — Call `remove_filter('wp_robots', 'wp_robots_noindex')` or suppress WordPress's default robots output when ThinkRank is managing it.

3. **Add permalink check to onboarding** — Consider redirecting users to set pretty permalinks after activation, since the sitemap won't work without them.

4. **Add build step to CI** — The `npm run build` step is required before testing but not documented prominently. Ensure CI/CD runs the build before deploying or packaging.

5. **Update test assertions** — `wp_thinkrank_instant_indexing_logs` and `content_quality` column are both in v1.10.0. Update the test plan to verify these with a v1.9.x baseline, or add truly new v1.11.0-specific schema checks.
